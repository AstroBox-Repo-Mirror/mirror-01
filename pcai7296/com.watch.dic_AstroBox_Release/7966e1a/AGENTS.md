# release_repo/ — AstroBox Submission Artifacts

Built from `npm run release` + helper scripts in `omo/`. This is **what gets uploaded to the AstroBox app marketplace**.

## Files

| File | Role |
|------|------|
| `com.watch.dic.release.1.0.0.rpk` | Signed installation package. Regenerated by `npm run release`. |
| `cover.png` | Marketplace cover image. Generated by `python omo/gen_poster.py` (or `gen_cover*.py` variants; v9 = current). |
| `icon.png` | App icon. Static. |
| `manifest.json` / `manifest_v2.json` | Submission metadata for AstroBox (different schema versions). |
| `README.md` | Submission README. |
| `preview/` | Directory of preview screenshots (01_home.png, 02_search.png, 03_results_en.png, 04_results_zh.png, ...). |

## Visual pipeline

1. **Cover** — `omo/gen_poster.py` reads `release_repo/preview/01_home.png` (must exist) + Xiaomi Band 10 skin from `~/.vela/sdk/skins/builtin/xiaomi_band_10/background_l.png` → outputs `release_repo/cover.png` (1800×1200).
2. **Visual QC** — `.opencode/instructions/poster-qc.md` workflow: send reference (e.g. `appstore/05_学习盒子高中.png`) + cover to GLM-4V-Flash; iterate.
3. **RPK** — `npm run release` produces `com.watch.dic.release.<ver>.rpk`.

## Visibility

The `release_repo/.git/` is a vendored AstroBox template; ignore it. The directory also tracks in git for backup purposes.

## ANTI-PATTERNS

- **Don't store release builds outside this dir** — the path is what AstroBox CLI expects.
- **Don't hand-edit cover.png / manifest.json** — regenerate via scripts.
- **Don't mix schema versions** in `manifest.json` — keep `manifest.json` and `manifest_v2.json` separate; pick one when submitting.
