# ui-v3 原型（可行性验证）

回答一个问题：**不靠 HTML 窗口，直接用宿主的 `ui-v3` 元素树，能不能做出接近
`web/`（HTML 版）的界面。**

## 结论先说

**能做出九成，但有三件事在宿主上做不到**，这会实实在在地改变观感：

| HTML 稿依赖 | 宿主 ui-v3 | 后果 |
| --- | --- | --- |
| `font-weight` 400/500/600 | **不支持** | 全界面同一个字重。层级只能靠字号落差 + 明度落差建立 |
| `box-shadow` / 渐变 | **不支持** | 没有卡片浮起感，只能靠实色深浅分层次 |
| 固定底栏（`position:fixed`） | 没有对应方法 | 导航只能挪到顶栏下方，靠一根指示条表示选中 |
| 百分比宽度 | `width` 只收 u32 | 进度条改成 N 段等宽小块点亮 |
| `letter-spacing` / `line-height` / `text-align` | **不支持** | 行内疏密、右对齐数值都要用 gap / flex-grow 模拟 |

这张表不是猜的：`HOST_PROP_WHITELIST` 是从 `C:\Program Files\AstroBox\AstroBox-ng.exe`
的字符串表里逐字抄出来的属性白名单（2.2.0）。**表外的属性宿主直接丢弃、不报错**，
所以用浏览器 CSS 预览会看到「字重分明」，真机上却是「一片平」。

## 为什么这个原型可信

`render.mjs` 只认那张白名单：白名单外的属性**整条丢弃、不近似**。
屏幕上没有字重、没有阴影，就是真机上没有 —— 预览不会骗人。
构建时会把被丢弃的属性名列出来（当前是「无」，说明节点树里没有用宿主不支持的东西）。

## 跑起来

```bash
cd astrobox-plugin/amakano2-import
node ui-v3-proto/build.mjs
# 输出 ui-v3-proto/out/index.html，五页并排、1:1 真机宽度 420px
```

## 文件

- `render.mjs` — 白名单 + 节点树 → HTML（**唯一**知道宿主能力边界的文件）
- `tree.mjs` — 五页的节点树，函数签名对齐 Rust 侧 `ui-core`，可直接搬
- `build.mjs` — 出图

## 还没验证的风险项

1. **`SVG` 元素**：宿主类型表里有 `SVG`，但内容（路径 markup）能否渲染没验过。
   底栏图标全押在它上面 —— 万一不行，只能退回「纯文字导航」或 `IMAGE` + PNG。
2. **`SCROLL-AREA` 横向滚动**：线路筛选 6 项在 400px 下必然超宽，要靠它。
   现有代码里 `scroll("x")` 在用，但没有横向滚动的真机截图佐证。
3. **`SWITCH`**：类型表里有，设置页的「自动打开游戏」用它，样式是否跟宿主一致未知。

这三项决定了要不要退回文字/色块方案，建议**先打一个小包验证**再全量搬。
